# ==============================================================================
# DEPLOY (SERVING-ONLY) REQUIREMENTS — Render free tier / slim Docker images
# ==============================================================================
# Exactly what `import app.main` + uvicorn need to serve /query. Verified by
# an import trace of the full serving path plus a blocked-import run of the
# whole pipeline (guardrails + retrieval + rerank + synthesis).
#
# EVERY direct dependency is pinned with `==`. Render rebuilds from scratch on
# every push, and this image is tuned to a *measured* peak of ~440 MB against a
# 512 MB ceiling. An unpinned transitive bump (or even a pinned direct dep
# pulling a different transitive) can silently reintroduce the OOM that the
# measurements below exist to prevent. These versions are the ones the
# measurements were taken against — if you bump one, re-measure before shipping:
#
#   docker build -t rag-app-slim .
#   docker run --rm --memory=512m --memory-swap=512m --cpus=0.1 \
#     --env-file .env -p 8000:8000 rag-app-slim
#   curl -m 300 localhost:8000/
#
# Intentionally EXCLUDED (present in requirements.txt, never loaded when
# serving): sentence-transformers/torch/CUDA (~3.8 GB of the image), and the
# ingestion + evals stack (unstructured, pdfplumber, python-pptx/docx, pypdf,
# beautifulsoup4, spacy chain, ragas, deepeval, langfuse, streamlit, pytz).
# langchain-google-vertexai is also excluded — serving runs without it.
#
# For local dev with ingestion/evals or EMBEDDING_PROVIDER=local, use
# requirements.txt instead.
